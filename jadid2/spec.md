# مُرجِع — نظام «مرجع ← مقطع نصي دقيق»

القاعدة الذهبية: كل استرجاع يرجع **نطاقاً نصياً دقيقاً** داخل ملف حقيقي موجود —
لا نص مولّد. ثلاثة محاور:

| المحور | المدخل | المخرَج | الحدود |
|---|---|---|---|
| تفسير | سورة + آية + كتاب تفسير | مقطع التفسير | بنيوي (فهرسة آية-بدقة في المصدر) |
| حديث | متن حديث + كتاب شرح | مقطع الاستشهاد/الشرح | shingle-حدودية على ذرات الكتاب |
| متن | عبارة متن + شرحه | مقطع الشرح | نفس الخوارزمية (اقتباسات «قوله») |

## المصادر (مستنسخة خارج الريبو، مثبّتة بالـcommit في `data/sources.json`)

- **التفسير**: `meibassam/mosahaf-tafseer` — 114 ملف JSON، كل آية
  `{ayah_number, text, tafsir:[{type,text}]}` — 8 تفاسير × 6236 آية (كاملة).
  الاسترجاع = lookup منظم؛ الصفحة تجلب ملف السورة من `raw.githubusercontent.com`
  وقت التشغيل (CORS مفتوح) — لا نسخ خام داخل des.
- **الحديث**: `AhmedBaset/hadith-json` — 50,884 حديثاً / 17 كتاباً.
  العينة المستعملة للمطابقة: بلوغ المرام (كوربوس الاستشهاد الفقهي) + الأربعين
  النووية + الأربعين القدسية = 1754 متناً بعد قصّ الإسناد.
- **الشرح**: `rlg/indexes/fiqh/real_index/data/*.units.jsonl` — الذرات = قطع
  نصية حرفية من الكتاب مع وحدات/عناوين. 8 كتب مفهرسة:
  المهذب، المجموع، المغني، الذخيرة، فتح القريب، الإقناع، بداية المجتهد، إعانة الطالبين.
- **متن←شرح**: `abi_shuja.units.jsonl` (متن) × `fath_qarib.units.jsonl` (شرحه).

## خوارزمية الحدود (`tools/search.py`)

1. تطبيع (`norm.py`): NFKC، إزالة الحركات/التطويل، توحيد الألف/ة/ى/ؤ/ئ، إسقاط الترقيم — نفس وصفة `akidsofi/tools/cut_texts.py`.
2. فهرس عكسي: 4-gram كلمات ← مواضع عالمية في تسلسل ذرات الكتاب.
3. كل إصابة shingle تعطي `(q_pos, g_pos)`؛ التطابق المتصل يقع على قطر
   `d = q_pos - g_pos` واحد — أطول سلسلة متتالية على قطر = أطول مقطع مشترك
   متصل، ويعبر حدود الذرات تلقائياً لأن المواضع عالمية.
4. المقطع = نطاق الذرات المغطّى للسلسلة + ذرة سياق قبل/بعد؛ دقة الحدود = مواضع
   الكلمات داخل ذرتي الطرفين.
5. عتبات: run ≥ 10 كلمات، أو run ≥ 6 مع تغطية ≥ 55% (للمتون القصيرة).

## القياس على العينة (`tools/eval.py` → `data/eval.json`)

- **تفسير**: 8/8 كتب × 6236/6236 آية — تغطية بنيوية مكتملة.
- **حديث←شرح**: 519 مطابقة من 1754 متن عينة (≈30%):
  المجموع 180، المغني 83، الذخيرة 76، بداية 63، المهذب 61، الإقناع 43،
  إعانة 12، فتح القريب 1. **دقة الحدود 100%** (519/519: السلسلة المتصلة تُوجد
  حرفياً داخل الذرات المُعادة — تحقق آلي). عينة تدقيق يدوية في
  `data/eval_sample.md` تُظهر اقتباسات حقيقية بنمط «لِقَوْلِهِ ﵊».
- **متن←شرح**: 315 عبارة من متن أبي شجاع مربوطة بمقاطع فتح القريب (تغطية ≥50%).

## التشغيل

```bash
# المصادر (خارج des — لا تُنسخ)
git clone https://github.com/meibassam/mosahaf-tafseer ~/repos/oss/mosahaf-tafseer
git clone https://github.com/AhmedBaset/hadith-json ~/repos/oss/hadith-json
# بناء الفهارس (تحتاج rlg مستنسخاً)
cd jadid2/tools && python3 build.py && python3 eval.py
# البرهان
cd ~/repos/des && python3 -m http.server 8899  # → /jadid2/
```

## ما ينقص للتعميم

- **كتب شرح الحديث الحقيقية** (فتح الباري، شرح النووي على مسلم…) ليست في
  المصادر — الشروح الفقهية تشرح الحديث **في سياق استدلالي** لا شرحاً متتابعاً.
  الخوارزمية جاهزة لأي كتاب بصيغة atoms؛ تعميمها على شرح حديثي يحتاج إدخال
  نصه (OpenITI هو المصدر الطبيعي).
- **التغطية ~30%** طبيعية: لا يستشهد الفقهاء بكل متون بلوغ المرام حرفياً —
  بعضها مقتطع أو معاد الصياغة. رفعها يتطلب مطابقة تقريبية (fuzzy) وأسانيد.
- ملفات mosahaf الكبيرة (البقرة ~15MB) تُجلب كاملة — يُفضّل لاحقاً فهرس
  آية→إزاحة بايت لجلب نطاقي (Range fetch).
- الذرات نفسها حدود تقريبية أحياناً (المقطع قد يبدأ/ينتهي وسط اقتباس مركّب) —
  التحسين: توسعة الحدود إلى حدود الوحدة الأقرب مع «قوله/أي/معناه».
