# SPEC — نواة «منصة تعلم محمد» (`jadid2/core`)

مواصفة هندسية للنواة. الأصل فيها كلام محمد نفسه (دستور، §1)؛ وما زاد
عليه قرار معماري موثّق في §8 ليصحّحه. قاعدة العمل: «نجرّب ببيانات
قليلة ونحسّن على العينة ثم نعمّم» — فالبنية تستوعب علماً واحداً
صغيراً أولاً، وتعميمها لاحق.

**النطاق**: نموذج بيانات الشجرة (§2)، محرك المهارات (§3)، حلقة الوكيل
(§4)، مصادر المحتوى المسبق (§5)، الواجهة الأولى (§6)، معايير القبول
القابلة للفحص (§7)، القرارات (§8). **خارج النطاق**: نموذج لغوي،
حسابات، مزامنة، بنك مشاريع، تعدد علوم.

## 1. الدستور (مستلّ من كلام محمد)

| المبدأ | أثره المعماري الملزم |
|---|---|
| وكيل يعرفه: يستقبل ويبدأ التدريس، الموضوع قابل للتغيير، هو من يقترح الاختبار/المشروع | محرك قواعد يقرأ سجل المتعلم؛ لا شاشة اختيار فارغة |
| الذرة: حجم حر، لها أب وقد يملك الأب أباً، ذرات→مفهوم→فكرة، تقييم يدوي مستمر | شجرة عقد بأب واحد؛ حقول تنقيح داخل الذرة |
| FSRS على المهارات: نجاح→موعد أبعد+تمرين أصعب، فشل→أقرب+أسهل | المجدول يعيد (موعد + مستوى) — §3 |
| نموذج مصطفى السعد: معلومة صغيرة + تمارين خبير متدرجة + «لا تنظر للحل قبل بذل الجهد» + قائمة صعب جانبية + جدول مراجعة | الحل محجوب بزر؛ `hardList` و`schedule` عنصرا واجهة دائمان |
| مشكلاته: النسيان، كره اختراع مشاريع، تضييع الوقت بالتفاصيل | الواجهة تقرر «ماذا الآن» ولا تعرض خيارات مفتوحة |
| الأولويات: شرعي›برمجة›إنجليزية›علوم. عربي أولاً، محلي بلا حسابات، مجاني | العينة شرعية؛ HTML+JS خام؛ localStorage فقط |
| المحتوى: خطط وأسئلة وتمارين مسبقة منتقاة لا مخترعة | المحتوى ملفات `*.js` في المستودع، لا توليد وقت التشغيل |

## 2. أنواع البيانات

### 2.1 `Tree` — ملف `tree.js` لكل علم (`window.MADRASA_TREE`)

| الحقل | النوع | إلزامي | الوصف |
|---|---|---|---|
| `id` | `string` (slug) | ✓ | معرف العلم، مثال `ilm-mustalah` |
| `title` | `string` | ✓ | اسم العلم للعرض |
| `nodes` | `Record<NodeId, Node>` | ✓ | خريطة مسطّحة — كل عقدة لها أب واحد |
| `order` | `NodeId[]` | ✓ | أوراق الذرات بترتيب الخطة التعليمية (يفصل ترتيب التدريس عن ترتيب العرض) |

### 2.2 `Node` — عقدة الشجرة

| الحقل | النوع | إلزامي | الوصف |
|---|---|---|---|
| `kind` | `'ilm'\|'bab'\|'concept'\|'atom'` | ✓ | `ilm` للجذر فقط؛ العمق غير مقيّد (يجوز باب بلا مفهوم، وذرة تحت علم) |
| `title` | `string` | ✓ | |
| `parent` | `NodeId\|null` | ✓ | `null` للجذر — «الأب وقد يملك الأب أباً» |
| `children` | `NodeId[]` | للحاويات | ترتيب العرض الشجري |
| `body` | `string` | للذرة | النص المعرفي — حجم حر (جملة أو صفحة) |
| `source` | `string` | – | مرجع النص |
| `skill.ex` | `Exercise[]` | للذرة | تمارين متدرجة منتقاة خبيراً |
| `quality` | `AtomQuality` | للذرة | حقول التنقيح اليدوي (دستور التقييم المستمر) |

`Exercise = { lv: 0|1|2, q: string, a: string }` — `lv`: 0 سهل، 1 متوسط، 2 صعب.
`AtomQuality = { score: 0..5, note: string, rev: int }` — تقييم محمد
للذرة نفسها وعدد مرات تنقيحها.

### 2.3 `AtomState` — حالة مهارة ذرة (تحت `store.atoms[nid]`)

| الحقل | النوع | الوصف |
|---|---|---|
| `lv` | `int ∈ [0,2]` | مستوى التمرين القادم (الصعوبة) |
| `reps` | `int` | تكرارات SM-2 الناجحة المتتالية |
| `ease` | `float ∈ [1.3,2.8]` | عامل سهولة SM-2 |
| `interval` | `int` (أيام) | الفاصل الحالي |
| `lastReview` | `ISO8601\|null` | لحظة آخر تسجيل؛ `null`=لم تُتعلَّم |
| `lapses` | `int` | عدد مرات النسيان |
| `hard` | `bool` | في «قائمة الصعب» — آخر نتيجة `fail` |
| `last` | `Outcome\|null` | آخر نتيجة مسجلة |

### 2.4 `Store` — `localStorage["madrasa_v1"]`

```
{ atoms: Record<NodeId, AtomState>,
  log:   LogEntry[],                 // سجل الخام — مادة «يتعلم عنه»
  planCursor: NodeId|null }
LogEntry = { nid: NodeId, outcome: Outcome, ts: int(ms) }
Outcome  = 'fail' | 'barely' | 'pass'
```

### 2.5 نتيجة التسجيل `RecordResult`

```
{ nextReview: ISODate(YYYY-MM-DD), intervalDays: int,
  level: 0|1|2, levelName: 'سهل'|'متوسط'|'صعب', mastered: bool }
```

## 3. محرك المهارات — FSRS-S (`engine.js`)

### 3.1 التوقيع (واجهة محمد المحددة: input=نتيجة تمرين، output=موعد+تمرين تالٍ)

```
record(nid: NodeId, outcome: Outcome) → RecordResult
```

### 3.2 الخوارزمية

```
q ← QUALITY[outcome]          // fail:1, barely:3, pass:5
a ← state(nid)                // أو الحالة الافتراضية
r ← FSRS.schedule(a, q)       // المجدول الزمني shared/fsrs.js (SM-2+)
a ← merge(a, r, lastReview=now, last=outcome)
lv: fail→max(0,lv−1) | barely→lv | pass→min(2,lv+1)
hard: fail→true | pass→false | barely→ثابتة
mastered ← (outcome='pass' ∧ lv=2)
log.push; planCursor ← nid; persist
return RecordResult
```

### 3.3 الحالات الحدية

| الحالة | السلوك المحدد |
|---|---|
| `outcome` خارج المجموعة | `throw` — لا تُسجَّل حالة ناقصة |
| ذرة جديدة (لا حالة) | حالة افتراضية: `lv=0, ease=2.5, reps=0` |
| `fail` عند `lv=0` | `lv` يبقى 0 (أرضية)، `hard=true`, الفاصل 1 يوم |
| `pass` عند `lv=2` | `mastered=true` في كل مرة؛ الفاصل يتمدد بلا مستوى جديد |
| `barely` | الموعد يُجدول (جودة 3) والمستوى لا يتغير و`hard` لا تُرفع |
| `nid` غير موجود في الشجرة | تُسجَّل الحالة ولا يظهر في الاستعلامات — التحقق مسؤولية الواجهة |
| `localStorage` تالف/غير مقروء | حالة فارغة جديدة — لا استرداد، لا خطأ للمستخدم |
| تسجيلان لنفس الذرة في يوم واحد | كلاهما يُسجَّل؛ `lastReview` الأخير هو المعتمد |

### 3.4 الاستعلامات

```
nextDate(nid)  → lastReview + interval (YYYY-MM-DD) | null
dueToday()     → ذرات nextDate ≤ اليوم، مرتبة تصاعدياً
nextNew()      → أول nid في order بلا lastReview
todayQueue()   → dueToday() ++ [nextNew()]   // ما يعرضه الوكيل عند الاستقبال
hardList()     → ذرات hard=true              // القائمة الجانبية للصعب
stats()        → {total, learned, due, hard, mastered}
path(nid)      → [علم…ذرة] فتات التنقل
conceptAtoms(cid), conceptMastered(cid)      // لاقتراح «اختبار المفهوم»
```

## 8. القرارات

**اتخذتها النواة (قابلة للنقض):**
1. الوكيل قواعد لا LLM — «يعرفه» من بياناته لا من نموذج لغوي؛ LLM
   تجميلي لاحقاً عبر `shared/llm.js`.
2. التقييم ثلاثي (أخطأت/بالكاد/نجحت): «بالكاد» نجاح بلا ترقية — أدنى
   توسيع يُعبّر عن «أصعب/أسهل» دون تشتيت.
3. مستويات ثلاثة ثابتة، والترقية/التنزيل داخلها.
4. الذرة هي وحدة الجدولة، والتمرين فرعها المتدرج.
5. «الصعب» = آخر نتيجة فشل؛ تُرفع عند أول `pass`.

**تحتاج قرار محمد لاحقاً:**
- FSRS-5 الحقيقي بدل SM-2+؟ (واجهة `record` لا تتغير)
- مصدر بنك المشاريع المتدرجة وشكله (روابط أم مهام منقولة)؟
- إشارات «يتعلم عنه»: زمن الإجابة؟ نسبة فشل لكل باب؟ — `log` جاهز،
  قواعد الاستنتاج غائبة.
- اختبار المفهوم: تمارينه الصعبة مجمعة (المبنى) أم أسئلة مستقلة؟
- علوم متعددة: ملف `tree.js` لكل علم + فهرس، أم شجرة أمّ واحدة؟
- التصدير: زر JSON كافٍ أم مزامنة حقيقية؟
