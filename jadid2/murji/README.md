# مُرجِع — آية + كتاب تفسير ← مقطع النص الدقيق cuisine

تكملة `jadid2/spec.md` + `tools/`: هناك الاسترجاع بنيوي (JSON مقطّع
مسبقاً)، وهنا المحرك يعيد اكتشاف مواضع الآيات داخل **نص الكتاب المتصل**
ثم يقطع حدود التفسير بينها.

## المدخل والمخرج

`lookup(surah, ayah)` → `{file, char_start, char_end, excerpt, confidence}`

- `file`: ملف المصدر (`wahy/data/tafsir/…json.gz`)
- `char_start/char_end`: حدود المقطع في **النص المعاد بناؤه** من الكتاب
  (بصمته `sha256_16` مسجّلة في الفهرس للتحقق)
- `confidence`: `high` (علامة «قوله تعالى» مصرّحة) / `medium` (اقتباس
  لفظي مثبت) / `low` (لا اقتباس — فجوة بين جارين محددين أو كتلة مشتركة)
  / `none` (لا شيء)

## الاستخدام

```bash
cd jadid2/murji/engine
python3 lookup.py index  --book ibn_kathir   # يكتب ../indexes/murji/
python3 lookup.py lookup --book saadi 2 255  # مقطع آية الكرسي
python3 lookup.py lookup --book ibn_kathir 36 1 --full
python3 eval.py                              # يولّد ../EVAL.md
```

## الفكرة

1. **إعادة بناء النص**: `vg` في مصدر الكتاب يربط الآيات بمجموعات
   (مجموعة قد تغطي آيات)؛ نسلكها بالترتيب القرآني ونلصق `x` — الناتج
   نص متصل «أعمى» لا يعرف الحدود، و`vg` نفسه يُستعمل أرضيةً ذهبية
   للتقييم فقط.
2. **مرشحو الاقتباس**: لكل آية كل 3-gram و2-gram بكل متغيرات الألف
   الخنجرية (الرسم العثماني «صرٰط» يقابل «الصرط/الصراط» في الكتب)؛
   مسح واحد للكتاب يجمع الإصابات، وكل إصابة تُمدَّد لأطول مقطع متصل.
3. **نقاط الاستشهاد**: «قوله/قال/يقول» + لفظ الجلالة قريباً = 3،
   «الآية/الكريمة» = 1، إحاطة نصية `﴿ { « "` قبل الاقتباس = 2.
4. **الاختيار العالمي**: أطول سلسلة مواقيت متزايدة موزونة (Fenwick
   DP) — موضع خطأ واحد لا يسمّم ما بعده؛ يُسقِط نفسه لأنه يكسر
   سلسلة كثيفة صحيحة.
5. **المقطع**: من بداية سياق الاستشهاد إلى بداية مقطع أول آية محددة
   تالية (أو ترويسة سورة موالية)؛ بلا اقتباس ← فجوة الجارين/الكتلة
   المشتركة بثقة `low`.

## التقييم

`EVAL.md` — 30 آية موزعة × 4 تفاسير (ابن كثير، السعدي، الجلالين،
الطبري): دقة المواضع المحددة على الكتاب كله ≈ 96–98%، ونسبة الإصابة
الدقيقة على العينة 15–25/30 صحيح + 2–14 واسع + 1–3 خاطئ لكل كتاب، مع
توثيق أسباب الفشل (مصادر خارج الترتيب، إعادة اقتباس داخل قصة/مقدمة،
المعوذتان المتشابهتان، آيات بلا اقتباس لفظي، مجموعات مصدر فارغة).

## مُرجِع-حديث — حديث + كتاب شرح ← مقطع النص الدقيق

النظير الحديثي: `lookup_hadith.py` يسترجع مقطع الشرح المقابل لحديث
داخل كتاب شرح متصل. المثال الملتزم: **جامع العلوم والحكم لابن رجب**
(شرح الأربعين النووية + زوائده الثمانية = 50 حديثاً)، نص OpenITI
`JK000071-ara1` في `data/` (انظر `data/sources.json`).

```bash
cd jadid2/murji/engine
python3 lookup_hadith.py index  --book jamic_ulum
python3 lookup_hadith.py lookup --book jamic_ulum 24
python3 lookup_hadith.py lookup --book jamic_ulum --text "إنما الأعمال بالنيات"
python3 eval_hadith.py                       # يولّد ../EVAL_HADITH.md
```

فروق عن نسخة التفسير:

- **المدخل**: رقم داخل الكتاب (`lookup(num)`) أو نص حر (`lookup_text`
  يعيّن أقرب حديث بتشابه جاكار ثم يسترجعه) — لا «رقم عالمي» للحديث.
- **صيغ متعددة**: لكل حديث تُجمَع روايات بديلة من متون الكتب الستة في
  `wahy/data/hadith/*.json.gz` (حقل `x` بلا إسناد) باحتواء idf≥0.5،
  إضافةً إلى متن النووي من `hadith/nawawi.js` — لأن الشرح قد يقتبس
  رواية غير لفظ النووي. زوائد ابن رجب (43-50) تُلتقط من الكتب الستة
  ببذور نصية `EXTRA_SEEDS`.
- **نقاط الاستشهاد**: «قال رسول الله / سمعت النبي / عن فلان قال /
  حدثنا» قبل المتن (+3/+1)، وتوقيع «رواه فلان / متفق عليه» بعده (+2)
  — عكس الآية، التخريج *يلي* المتن.
- **حدود المقاطع**: ترويسات «الحديث N» (50/50 موجودة ومتزايدة)
  فبداية مقطع الحديث التالي.
- **كشف المعنى**: حديث بلا لفظ مطابق ← نافذة منزلقة بين جاريه
  المحددين باحتواء idf؛ النجاح يُرجَع `kind=meaning` بثقة `low`
  — موثّق في الفهرس لا مموّه.
- **الأرضية الذهبية للتقييم**: الترويسات نفسها (الحدث N → N+1)؛
  الحكم على موضع *الاقتباس* لا على حدود المقطع، فلا دائرية.

## التقييم (حديث)

`EVAL_HADITH.md` — 30 حديثاً موزعة (أول الأربعين + أحاديث مشهورة +
كل الزوائد): **30/30 صحيح** على العينة و**50/50 (100%)** دقة المواضع

## مُرجِع-فقه — مسألة/عبارة + كتاب شرح ← مقطع النص الدقيق

النظير الفقهي: `lookup_fiqh.py` يسترجع المقطع الذي يعالج مسألة فقهية
داخل كتاب شرح متصل. الكتاب الملتزم: **المبدع شرح المقنع لابن مفلح**
(من نصوص rlg؛ السبب في `EVAL_FIQH.md`) — 18471 مرشح فقرة و672 ترويسة.

```bash
cd jadid2/murji/engine
python3 lookup_fiqh.py index  --book mubdi
python3 lookup_fiqh.py lookup --book mubdi --text 'حكم بيع الحرير لكافر'
python3 eval_fiqh.py                          # يولّد ../EVAL_FIQH.md
```

فروق عن النسختين:

- **المرشحون علامات فقهية لا اقتباسات**: أسطر «فرع/مسألة/شرط (إذا/لو)»
  + اقتباسات المتن «(…)» + «قال <سلطة>» + حواشي (تنبيه/تذنيب/فائدة)،
  لكلٍّ رتبةٌ ومقطعه يمتد حتى أول علامة برتبة ≤ رتبته — فيضمّ اقتباس
  المتن فروعه التابعة، والمسألة شرحها.
- **تقسيم الباب**: ترويسات «كتاب/باب/فصل/قسم» القصيرة تُعيّن لكل مرشح
  بابه الحاوي (يُعاد `sec` للتحقق ومكافأة نطاق).
- **ترجيح الصيغة**: ضربات n-gram داخل صيغة المرشح (أول سطرين) أثقل
  ×5 من مبعثرة في عمق المقطع — سؤال مسألة غايته صيغتها لا كل ما
  يليها؛ وأولوية صيغ المسائل على متن المقرر.
- **توكنات أرقام شفافة**: إحالات «(¬٧)» تحذف من مطابقة السلاسل لا
  تكسرها، والتشكيل والتطويل داخل الكلمات لا يشقّ التوكنة.
- **كشف المعنى**: بلا لفظ ← نافذة منزلقة باحتواء idf →
  `kind=meaning` بثقة `low` موثّقة.
- **التقييم بمراسي لغوية** لا بالفهرس نفسه — لا دائرية.

## التقييم (فقه)

`EVAL_FIQH.md` — 30 مسألة معروفة موزعة على 18 باباً:
