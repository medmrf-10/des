# مواصفة تصنيف الذرات — annotations.json

أنت مصنّف معرفي شرعي. لكل ذرة في السلسلة المكلّف بها، أصدر تصنيفاً بعد قراءة نصّها الفعلي
(العنوان + الوسوم الأصلية + أول ~300 حرف من النص، مجهّزة لك في ملفات chunks).

لا تعدّل `index.json` إطلاقاً. الناتج ملف جانبي جديد: `jadid2/atoms/<series>/annotations.json`.

## مخرجات كل ذرة

```json
{"kind":"معلومة|مهارة","main_tag":"...","sub_tags":["..."],"difficulty":1}
```

## main_tag — قائمة ثابتة (14)

`عقيدة، فقه، أصول، نحو، صرف، بلاغة، حديث، مصطلح، تفسير، لغة، تزكية، أدب، سيرة، أخرى`

- احكم على **موضوع النص** لا على اسم السلسلة ولا على العنوان وحده.
- مواعظ/خطب/ترغيب وتهذيب نفسي → `تزكية`. آداب وسلوك اجتماعي/علمي → `أدب`.
- مقدمات إدارية، افتتاحيات، خواتم، دعاء، إعلانات — بلا محتوى علمي → `أخرى`.
- مقطع قرآني/حديثي داخل درس يُصنَّف بموضوع شرحه (تفسير/حديث فقط إن كان الشرح تفسيراً أو حديثياً فعلاً).

## kind

- `معلومة` (الافتراضي): محتوى نظري يُفهم ويُحفظ — شرح، تعريف، حكم، نص متن، قصة، تنبيه.
- `مهارة`: فقط إن كان النص **تدريباً عملياً على مهارة** — إعراب جملة، تصريف فعل، تخريج حديث،
  تطبيق قاعدة على مثال، تدريب استنباطي. «شرح قاعدة الإعراب» = معلومة؛ «أعرب هذه الجملة / طبّق» = مهارة.
- عند الشك اختر `معلومة` وسجّل الذرة في uncertain.

## difficulty — 1..5 من عمق المبحث وطبيعته

| القيمة | الوصف |
|---|---|
| 1 | تأسيسي بديهي: تعريفات أولى، مقدمة، إداريات، قصة وعظية بسيطة |
| 2 | مبتدئ: قاعدة أو مسألة بسيطة بأمثلة مباشرة |
| 3 | متوسط: شرح قاعدة، تفريع مألوف، ضبط مصطلح |
| 4 | متقدم: خلافات، تطبيق مركب، تدقيقات، جمع بين أدلة |
| 5 | عالٍ: تركيب/استنباط عميق، حواشٍ دقيقة، تحريرات أصولية/كلامية |

استرشد بمستوى السلسلة (تمهيدي/أول/ثانٍ/رابع/حواشي) لكن الحكم النهائي على النص.

## sub_tags

1–3 وسوم دقيقة بالعربية تفصّل المبحث (مثل: `أقسام_الكلمة`، `المفعول_به`، `توحيد_الربوبية`،
`أقسام_الحديث`، `براعة_الاستهلال`، `شروط_الصلاة`). استعمل `_` بدل المسافة. الأفضل الانتقاء من
`tags` الأصلية للذرة عند كفايتها وإضافة الأدق عند الحاجة. رتّبها من الأعم إلى الأخص.

## سير العمل (إلزامي)

1. مدخلاتك جاهزة في `jadid2/annotation_work/chunks/<series>/chunk_NNN.jsonl` — كل سطر:
   `{"id","title","tags","text"}`. عدد الأسطر = عدد الذرات، والترتيب = ترتيب index.json.
2. عالج الملفات بالترتيب `chunk_001` ثم `chunk_002` … ولا تخطَّ سطراً.
3. لكل chunk أنشئ `jadid2/annotation_work/parts/<series>/chunk_NNN.jsonl` **بنفس الاسم**،
   سطراً لكل ذرة:
   `{"id":"<id>","kind":"...","main_tag":"...","sub_tags":[...],"difficulty":N}`
   لا أسطر فارغة ولا تعليقات ولا حقول زائدة.
4. بعد إكمال كل الأجزاء نفّذ:
   `python3 jadid2/annotation_work/assemble.py "<series>"`
   يجمع الأجزاء، يتحقق من التغطية الكاملة وصحة القيم، ويكتب
   `jadid2/atoms/<series>/annotations.json`. إن فشل: صحّح أسطر parts المُبلَّغ عنها وأعد التشغيل حتى OK.
5. Git:
   ```
   git add "jadid2/atoms/<series>/annotations.json"
   git commit -m "annotations: <series>"
   git push -u origin HEAD:<branch>
   ```
6. المخرجات المنظمة: `branch`، `atoms_total`، `atoms_annotated`، `skills` (عدد ذرات مهارة)،
   `uncertain` (حتى 15 عنصراً `{id, why}` للذرات التي لم تكن واثقاً من تصنيفها)، `notes`.

## ملاحظات

- الذرات ذات `inferred=true` أو العناوين العامة (افتتاحية/خاتمة/مراجعة) لا تُعفى من التصنيف —
  صنّفها على نصها؛ الإدارية منها → `أخرى` + difficulty=1 + kind=معلومة.
- النصوص تفريغات صوتية لدروس: قد تشمل مداخلات طلاب وأسئلة — صنّف على المضمون العلمي الغالب.
- لا تخترع وسم `main_tag` خارج القائمة. `sub_tags` حرة لكن دقيقة ومفيدة لبناء سلاسل متطلبات.
