# المنهج الشامي القابل للتطبيق برمجياً — مختبر الحديث

> خلاصة منهج صالح أحمد الشامي (دوما 1934) في الجمع والترتيب والحكم، مترجمة
> إلى قواعد قابلة للتنفيذ على بيانات `wahy/data/hadith/*-det.json.gz`
> (والتي هي أصلاً تجسيد رقمي لمنهجه — انظر `wahy/build.py`).

## ١) وحدة العمل: المعنى لا الرواية

الشامي لا يتعامل مع «الحديث رقم» بل مع **المعنى الموحّد**: يجمع كل طرق وروايات
الحديث الواحد تحت مدخل واحد ثم يحذف المكرر (البخاري+مسلم: 10596 ← 3896).
في البيانات: مفتاح `g` في كل كتاب هو **معرّف المعنى القانوني المشترك**
(`group_id` من قاعدة hadith-kg) — نفس `gid` في أي كتاب = نفس المعنى،
و`g.x` يعطي أول رقم حديث مقابل في كل كتاب آخر.

**القاعدة البرمجية:** كل التحليل والترجيح يجري على `gid`، والروايات
(`hs`، و`d`/`s`) هي شواهده لا ذوات مستقلة.

## ٢) خط أنابيب الجمع — طبقات الزوائد

منهج الشامي تراكمي بطبقات ثابتة الترتيب؛ كل طبقة تضيف فقط المعاني غير
المُلتقطة سابقاً:

```
الصحيحان (الجامع بين الصحيحين)
→ السنن الأربعة + الدارمي (زوائد السنن)
→ الموطأ + المسند (زوائد الموطأ والمسند)
→ السنن الكبرى للبيهقي
→ مجمع الزوائد للهيثمي
→ ابن خزيمة + ابن حبان + المستدرك
→ جامع الأصول التسعة / معالم السنة النبوية (الخلاصة)
```

**القاعدة البرمجية:** `book_coverage(gid)` = أعلى طبقة (أقرب للصحيحين)
يظهر فيها المعنى. أحاديث «الزيادة» = معاني بلا bukhari/muslim في مجموعتها —
تحسب فوراً بالأداة (`match`).

## ٣) التصنيف الموضوعي — شجرة المقاصد

قسّم الشامي السنة إلى أبواب مقاصدية كبرى (١٠ في الجامع، ١٣ في بيانات وحي).
في البيانات: `topics.json.gz → t` شجرة `{n,p,l,b}` بعمق ١٠ مستويات
(الأوراق تربط معانٍ عبر `g`: `topic → [gid]`).

## ٤) قواعد الترجيح بين الروايات — قابلة للتطبيق الآن

حقول `s[hadith] = [[hukum_sanad, [رواة...]], ...]` تحمل حكماً نصياً جاهزاً
لكل سند، يمكن استخلاص إشاراته آلياً:

| إشارة في نص الحكم | القراءة القابلة للترميز |
|---|---|
| `إسناده متصل` | سند متصل — الدرجة الأساسية للقبول |
| `موضع تعليق` | سند معلّق (حذف شيخ المصنف أو أكثر) — نقص اتصال |
| `موضع إرسال` | مرسل (سقوط الصحابي) — ضعف اتصال |
| `ضعيف ويحسن إذا توبع` | قابل للارتقاء بالمتابعات/الشواهد |
| `عدا فلان وهو صدوق…` | تعيين الراوي الأضعف في السلسلة (حلقة الضعف) |
| `موضع تعليق` (في قائمة الرواة كعنصر) | عقدة صورية تمثل معلقات البخاري — لا تُحسب راوياً |

### شجرة قرار مبسطة (مقترحة للمختبر)

```
لكل سند s:
  ١. اتصال: إن وجدت «موضع تعليق» كراوٍ أو في الحكم → معلق/مرسل ⇒ يدخل كشاهد لا أصل
  ٢. لكل راوٍ: ابحث درجته في تقريب التهذيب (shami_sources.json)
     → أضعف راوٍ يحدد سقف السند (قاعدة «السند بأضعف حلقة»)
     → عزل راوٍ ضعيف من كبار الأئمة («عدا فلان وهو صدوق…») ⇒ خصم جزئي لا إسقاط
  ٣. تدليس: راوٍ من المدلسين (تعريف أهل التقديس) + صيغة «عن» → علم إنذار
  ٤. ارتقاء: إذا تعددت الطرق إلى نفس gid وضعفت منفردة → حسن لغيره
```

### تصنيف الرواة — جدول الدرجات (من تقريب التهذيب)

```
ثقة ثبت / حافظ متقن   = 6
ثقة                    = 5
صدوق                   = 4
صدوق يخطئ / له أوهام / سيئ الحفظ = 3
مقبول بشرط المتابعة / لين        = 2
مجهول / مبهم           = 1
ضعيف / متروك / متهم   = 0
كذاب / وضاع            = -1
```

## ٥) حكم المعنى الموحد — ما تقوله البيانات فعلياً

`g.h` (الحكم) **متطابق عبر الكتب لنفس gid** (تحقّق: صفر اختلاف في
14191 مجموعة عبر الستة) — أي أن الحكم هو **حكم الجامع/المنهج على المعنى**
(شبيه بما يفعله الشامي) وليس حكم كل مصنّف على روايته.
مفردات الحكم المرصودة: `صحيح، حسن، ضعيف، شديد الضعف، متهم بالوضع، موضوع`.
قواعد الشامي العملية: الأصل صحيح الصحيحين؛ خارجها يُحكم بجمع الطرق —
والضعيف بالمتابعات يرتقي حسناً، وكثرة الطرق والصحابة تقوّي المعنى.

**إشارتان جاهزتان للتواتر المعنوي:**
- `g.s` = `sahaba_qty` — عدد الصحابة الذين رووا المعنى
- `g.r` = `repeat_qty` — عدد مرات ظهور المعنى في الأمهات

## ٦) حدود وملاحظات للتنفيذ

- «موضع تعليق» يظهر في قائمة الرواة كاسم راوٍ صوري — تصفية إلزامية قبل بناء الشبكة
- أسماء الرواة طويلة بالأنساب وتتفاوت في العمق بين الكتب — التطبيع المستخدم في
  `hadith_analysis.py` (تجريد التشكيل + توحيد الهمزات/الألف المقصورة) كافٍ
  للكتب الستة لأن المصدر موحد؛ للمطابقة مع نصوص خارجية استعمل تبصير المنتبه
- `hukm` المعنى ليس رأي كل مصنّف — لا تستنتج «اختلاف المصنفين» منه
- `sahaba_qty`/`repeat_qty` مقاييس مساندة لا حاسمة — المعنى المشهور ضعيفُه لا يصح بكثرة الرواية وحدها
